# 게시판으로 자동 업데이트

데이터도구실 게시글을 읽어 새 버전을 확인하고, 설치까지 진행하는 기능.

## 왜 옮기는가

**본청에서 GitHub이 막혀 있다.** 이 프로그램을 가장 많이 쓸 곳에서 자동 업데이트가
동작하지 않는다. 학교는 되지만 본청이 안 되면 옮길 이유로 충분하다.

**`file_automation_tools_tk`가 이미 같은 방식을 쓰고 있다.** 게시글 본문에 표식을
심어 두고 앱이 그 글을 읽는다. 검증된 방식이고, 같은 게시판에서 여러 앱을 함께
관리할 수 있다. 다만 그 도구는 "새 버전이 있다"고 알리기만 하고 설치는 사람이 한다.
여기서는 설치까지 간다.

## 반드시 알아야 할 제약

**게시판 첨부는 고정 주소가 없다.** 파일을 다시 올리면 `fileSid`가 바뀐다.
Tauri 업데이터 플러그인은 고정 주소에서 `latest.json`을 받아야 하므로 쓸 수 없다.
그래서 tk 도구처럼 **글 본문**을 읽는다. 글 보기 주소(`dataSid`)는 바뀌지 않는다.

**게시판이 exe 첨부를 받지 않는다.** 설치본을 ZIP으로 감싸 올린다.
ZIP은 운반 수단일 뿐이고, **서명은 압축을 푼 exe에 대해 확인한다.**
그래서 배포 워크플로가 지금 만드는 `.sig` 파일을 그대로 쓸 수 있고,
GitHub Actions를 고칠 필요가 없다. ZIP이 변조되면 안의 exe도 달라지므로
서명에서 걸린다. ZIP 자체에 따로 서명할 이유가 없다.

**서명 검증은 뺄 수 없다.** 받은 파일을 그대로 실행하기 때문이다. 검증이 없으면
설치 파일을 바꿔치기하는 것만으로 모든 PC에서 임의 코드가 돈다.
지금 GitHub 배포에 쓰는 minisign 키를 그대로 쓴다. 키를 새로 만들 필요가 없고,
서명 파일(`.sig`)은 448자짜리 base64 한 줄이라 표식에 같이 실을 수 있다.

**TLS 검증을 끄지 않는다.** tk 도구는 `CERT_NONE`으로 껐다. 버전 문자열만 읽을 때는
감수할 만하지만 실행 파일을 받을 때는 다르다. 관공서 인증서 문제로 실패하면
그때 가서 원인을 보고 다룬다. 조용히 끄지 않는다.

## 표식 형식

tk 도구와 같은 문법을 쓴다. 같은 글에서 여러 앱을 함께 관리할 수 있다.

```
[업데이트정보]id=JBEDT-0005|앱=JB업무ON|버전=1.2.5|다운로드=https://www.jbe.go.kr/board/download.jbe?...&fileSid=NNNNNN|서명=dW50cnVzdGVkIGNvbW1lbnQ6...
```

| 항목 | 뜻 |
|---|---|
| `id` | 앱 고유번호. 이것만 고정이면 나머지는 자유롭게 바꿔도 된다 |
| `앱` | 사람이 보라고 넣는 이름. 프로그램은 무시한다 |
| `버전` | `1.2.5` 형태 |
| `다운로드` | 설치본 ZIP의 첨부 링크 주소 |
| `서명` | `.sig` 파일 내용 그대로. base64라 `|`가 섞이지 않는다 |

tk 도구와 같은 형식이고, `서명` 하나만 더 붙는다.

**첨부 링크를 그대로 적는다.** 파일을 다시 올리면 `fileSid`가 바뀌므로 표식도 함께
고쳐야 하지만, 어차피 배포할 때마다 `버전`과 `서명`을 고치므로 부담이 늘지 않는다.

게시글 주소를 적고 앱이 그 글의 첨부를 찾게 하는 방법도 생각했지만 쓰지 않는다.
표식을 어차피 매번 고치므로 얻는 것이 없고, **게시판 HTML 구조에 의존하게 된다.**
홈페이지가 개편되면 이미 배포된 앱들이 조용히 업데이트를 못 하게 되고,
그때는 고칠 방법이 없다.

다만 코드는 게시글 주소도 받아 준다. `다운로드` 값에 `download.jbe`가 없으면
그 주소를 게시글로 보고 열어서 첨부를 찾는다. 나중에 필요해지면 쓸 수 있는
뒷문이고, 평소에는 쓰지 않는다. 그 글에 ZIP이 여러 개면 `파일=이름조각`으로 고른다.

첨부는 이런 모양이고, `download.jbe`가 들어간 주소와 `title`의 파일 이름을 본다.

```html
<p class="bbs_filedown">
  <a href="/board/download.jbe?...&fileSid=715387" title="이름.zip" class="ico_file">이름.zip (12 kb)</a>
</p>
```

ZIP 첨부가 하나면 그것을 쓴다. 여러 개면 어느 것인지 알 수 없으므로 멈추고,
표식에 `파일=JB업무ON`처럼 이름 조각을 넣으라고 알린다. 배포 게시글에 매뉴얼 같은
다른 ZIP이 함께 붙는 경우를 위한 장치다.

표식은 **서식 없이 한 줄로** 넣는다. 중간에 태그가 끼면 거기서 잘린다.

## 동작 흐름

```
시작 1.8초 뒤 (또는 설정에서 '지금 확인')
  → 게시글 HTML 받기
  → id=JBEDT-0005 표식 찾기, 버전 비교
  → 더 높으면 표식의 다운로드 주소에서 ZIP 받기
  → 압축 안의 exe 하나 꺼내기
  → minisign 서명 확인 — 어긋나면 아무것도 남기지 않고 멈춘다
  → 화면 위쪽에 "새 버전 1.2.5를 받아 두었습니다 / 지금 적용"
  → 누르면 설치 실행 후 앱 종료
```

받아 두기만 하고 적용 시점은 사용자가 고르는 지금 방식을 그대로 유지한다.
작업 중에 앱이 갑자기 재시작되면 곤란하다.

ZIP 안의 경로는 쓰지 않는다. exe 하나만 메모리로 꺼내 우리가 정한 이름으로
저장하므로, 압축 파일이 이상한 경로를 담고 있어도 영향이 없다.

## 설치 실행

```
<설치본> /UPDATE /P /R
```

| 인자 | 뜻 |
|---|---|
| `/UPDATE` | 갱신 모드. 이전 버전을 지우지 않고 바로 덮는다 |
| `/P` | 진행 막대만 보이고 누를 것이 없다 |
| `/R` | 설치가 끝나면 앱을 다시 실행한다 |

빌드 결과로 나온 `src-tauri/target/release/nsis/x64/installer.nsi`에서 확인한 인자다.
설치본이 `currentUser` 모드라 관리자 권한이 필요 없다.

완전 무음(`/S`)이 아니라 `/P`를 쓰는 이유는, 실패했을 때 사용자가 알 수 있어야 하기
때문이다. 탐색기 우클릭 메뉴에서 앱을 띄우기로 한 것과 같은 판단이다.

## GitHub은 어떻게 하는가

**앱은 게시판만 본다.** 두 곳을 다 보면 버전이 갈린다. 태그를 밀면 GitHub에는
자동으로 올라가지만 게시판은 사람이 글을 고쳐야 하므로, 게시판이 항상 뒤처진다.
이 상태에서 폴백을 두면 학교는 새 버전, 본청은 옛 버전이 되어 문의가 늘어난다.

GitHub Releases는 그대로 둔다. 설치본을 만들고 서명하는 곳이자 보관소다.
게시판에 올릴 파일도 거기서 받아 쓴다.

게시글을 못 읽으면 조용히 넘어간다. 업데이트가 안 될 뿐 앱은 그대로 동작한다.

## 바뀐 곳

| 파일 | 무엇을 |
|---|---|
| `update-config.json` | `app.app_id`, `app.post_url`, `app.public_key` 추가 |
| `src-tauri/src/board_update.rs` | 새 파일. 확인·내려받기·적용 명령 세 개 |
| `src-tauri/src/updates.rs` | `config_path`를 같은 크레이트에서 쓸 수 있게 공개 |
| `src-tauri/Cargo.toml` | `minisign-verify` 추가 |
| `src/lib/updater.ts` | 플러그인 대신 새 명령을 부른다 |
| `scripts/print_board_marker.ps1` | 새 파일. 붙여 넣을 표식 한 줄을 만든다 |

`useAutoUpdater.ts`와 설정 화면은 고치지 않았다. 부르는 함수 이름이 그대로라서
화면 위쪽 안내와 '지금 적용' 동작이 예전과 똑같이 남는다.

`tauri-plugin-updater`는 당장 지우지 않는다. 게시판 경로가 실제로 도는 것을 확인한
뒤에 뺀다.

## 배포 절차가 어떻게 바뀌는가

지금까지는 태그만 밀면 끝이었다. 앞으로는 한 단계가 늘어난다.

1. `scripts/set_version.ps1`로 버전을 올리고 태그를 민다 (지금과 같음)
2. GitHub Actions가 설치본과 `.sig`를 만든다 (지금과 같음)
3. **설치본을 ZIP으로 묶어 게시글에 첨부하고, 표식 한 줄을 갈아 끼운다** (새로 생김)

3번에서 서명을 손으로 옮겨 적으면 거의 틀린다. 한 글자만 어긋나도 설치가 거부된다.

ZIP을 첨부해 글을 저장한 뒤, 그 첨부 링크를 우클릭해 주소를 복사하고 넘긴다.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\print_board_marker.ps1 `
    -Version 1.2.5 -DownloadUrl "https://www.jbe.go.kr/board/download.jbe?...&fileSid=123456"
```

버전과 `.sig`를 읽어 붙여 넣을 한 줄을 만들고 클립보드에도 넣는다.
표식 줄을 통째로 갈아 끼우면 된다.

## 확인 방법

1. 게시글에 표식을 넣고 앱보다 낮은 버전을 적어 본다 → 아무 일도 없어야 한다
2. 높은 버전으로 고친다 → 받아 두었다는 안내가 떠야 한다
3. 표식의 `서명` 값을 한 글자 고친다 → 검증에 막혀 설치가 시작되지 않아야 한다
4. 게시글 주소를 없는 주소로 바꾼다 → 조용히 넘어가고 앱은 정상이어야 한다
5. 본청 망에서 1~2를 다시 해 본다

3번이 가장 중요하다. 이게 안 막히면 서명 검증이 동작하지 않는 것이다.

## 나중에

- 내려받는 동안 진행률이 나오지 않는다. Rust가 한 번에 받기 때문이다.
  60MB라 느린 망에서는 답답할 수 있다. 필요해지면 조각내 받으며 이벤트를 올린다
- 게시판 경로가 자리 잡으면 `tauri-plugin-updater`와 GitHub endpoint 설정을 뺀다
- 표식을 여러 앱이 함께 쓰는 만큼, tk 도구의 `id`(`JBEDT-0003`)와 겹치지 않게 둔다
