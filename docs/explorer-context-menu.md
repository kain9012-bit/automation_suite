# 탐색기 우클릭 메뉴

윈도우 탐색기에서 파일이나 폴더를 고르고 우클릭해 JB업무ON의 도구를 바로 부르는 기능.

## 왜 이렇게 만드는가

**1단계에서는 앱을 연다.** 창 없이 조용히 처리하는 방식이 빨라 보이지만, 실패했을 때
사용자가 아무것도 모르게 된다. 창이 열리면 진행 상황과 오류가 그대로 보이고
알림 플러그인도 필요 없다. 충분히 검증된 단순 기능만 나중에 무음 실행으로 옮긴다.

**어떤 도구를 메뉴에 넣을지는 사용자가 고른다.** 탐색기 우클릭은 모두가 공유하는
좁은 공간이라 항목이 늘어나면 금방 성가셔진다. 관리자가 목록을 정하지 않고
각자 필요한 것만 켜게 한다.

## 반드시 알아야 할 제약

**파일을 여러 개 골라도 Windows는 명령을 파일 개수만큼 각각 실행한다.**
PDF 3개를 고르면 프로그램이 경로 하나씩 들고 세 번 뜬다. 15~16개를 넘으면
아예 실행되지 않는다. 그래서 경로를 모으는 과정이 반드시 필요하다.

JB업무ON은 중복 실행 방지(`tauri-plugin-single-instance`)가 이미 들어 있어서,
두 번째 실행의 인자가 떠 있는 앱으로 전달된다. 이걸 재사용해 경로를 모은다.

**Windows 11에서는 `더 많은 옵션 표시` 안에 들어간다.** 첫 번째 메뉴에 띄우려면
MSIX 패키징과 COM 핸들러가 필요한데, MSIX는 코드 서명 인증서가 없으면 설치가
안 된다. 인증서를 확보하기 전까지는 손대지 않는다.

## 동작 흐름

```
PDF 3개 선택 → 우클릭 → 선택한 PDF 병합
  → 명령 3번 실행 (각각 경로 1개)
  → single-instance가 떠 있는 앱으로 인자 전달
  → 0.8초 모았다가 앱이 앞으로 나오며 PDF 병합 화면 열림
  → 파일 3개가 이미 담긴 상태. 사용자는 실행만 누른다
```

앱이 꺼져 있으면 첫 실행이 앱을 띄운다. 이때는 창이 보여야 하므로 `--tray`를 붙이지 않는다.

## 매니페스트 선언

`context_menu` 블록이 있는 도구만 설정 목록에 나타난다.

```json
"context_menu": {
  "targets": ["pdf"],
  "label": "선택한 PDF 병합",
  "multiple": true
}
```

| 항목 | 뜻 |
|---|---|
| `targets` | 확장자 목록(`["pdf", "xlsx"]`) 또는 `["folder"]` |
| `label` | 우클릭 메뉴에 보일 문구 |
| `multiple` | 여러 개를 골라 한 번에 처리하는 도구인지 |

옵션을 반드시 골라야 하는 도구(엑셀 분할의 기준 열 등)는 선언하지 않는다.

## 레지스트리

`HKCU`에만 쓴다. 관리자 권한이 필요 없고, 설치본이 `currentUser` 모드라 잘 맞는다.
자동 시작 설정에서 이미 `reg` 명령을 쓰고 있으므로 같은 방식으로 처리한다.

```
파일:   HKCU\Software\Classes\SystemFileAssociations\.pdf\shell\JBEduON.<도구ID>
폴더:   HKCU\Software\Classes\Directory\shell\JBEduON.<도구ID>

  (기본값)          = 메뉴에 보일 문구
  Icon              = 앱 실행 파일 경로
  command\(기본값)  = "<앱 경로>" --open-with <도구ID> --path "%1"
```

키 이름을 `JBEduON.` 으로 시작하게 두면 제거할 때 한 번에 찾을 수 있다.

## 정리

앱이 만든 키는 설치 제거 프로그램이 알지 못한다. 그대로 두면 앱을 지운 뒤에도
메뉴가 남아 눌러도 아무 일이 일어나지 않는다. 두 곳에서 지운다.

- **설치 제거할 때**: `src-tauri/installer-hooks.nsh`의 `NSIS_HOOK_PREUNINSTALL`이
  두 위치를 훑으며 `JBEduON.` 으로 시작하는 키를 지운다. 어떤 확장자를 켜 뒀는지는
  사람마다 다르므로 목록을 미리 적어 둘 수 없어 훑는 방식을 쓴다.
- **설정 화면의 `모두 해제`**: `clear_context_menus`가 같은 일을 앱 안에서 한다.
  훅이 놓친 것이나 이름이 바뀐 옛 도구가 남긴 것도 이걸로 정리된다.

## 1단계 시범 대상

사용 빈도가 높고 옵션이 거의 없는 것부터. 매니페스트에 `context_menu`를 선언해 뒀고,
실제로 켜는 것은 사용자가 설정 화면에서 고른다.

| 도구 | 대상 | 메뉴 문구 |
|---|---|---|
| `pdf_merge` | `.pdf` | 선택한 PDF 취합 |
| `pdf_compress` | `.pdf` | PDF 용량 줄이기 |
| `file_inventory` | 폴더 | 이 폴더 파일 목록 만들기 |
| `hwp_to_hwpx_converter` | `.hwp` | HWPX로 변환 |

실제로 쓰이는지 보고 늘린다.

## 확인 방법

1. `scripts/dev.ps1`로 띄우고 설정 → 탐색기 우클릭 메뉴에서 하나를 켠다.
2. 탐색기에서 PDF 여러 개를 골라 우클릭(Windows 11은 `더 많은 옵션 표시`).
3. 앱이 앞으로 나오고 해당 도구 화면에 파일이 전부 담겨 있으면 정상.
4. 앱을 완전히 종료한 뒤 같은 동작을 한 번 더 해서, 꺼져 있을 때도 열리는지 본다.
5. 설정에서 끄고 나서 우클릭 메뉴에서 사라지는지 확인한다.

개발 모드에서 등록하면 `command` 값이 개발용 실행 파일을 가리킨다.
설치본으로 바꾼 뒤에는 한 번 껐다 켜서 경로를 다시 쓰게 한다.
