# JB업무ON

**반복 업무를 간단하게 — 전북교육 업무도구 통합 프로그램**

엑셀 취합과 정리, PDF·한글 문서 작업, 자료 수집, 파일 정리처럼 매번 손으로 되풀이하던 일을
**41개 도구**로 묶은 Windows 데스크톱 프로그램입니다. 도구마다 따로 찾아 내려받을 필요 없이,
하나의 프로그램에서 고르고 바로 실행합니다. 만든 곳은 전북특별자치도교육청 정책기획과 빅데이터팀입니다.

## 왜 만들었나

### 같은 일을, 매번 처음부터

학교와 기관의 일에는 형식만 조금씩 다른 반복 작업이 많습니다. 여러 학교에서 받은 엑셀을 하나로 합치고,
연수 이수증을 한 장씩 나눠 이름을 붙이고, 한글 문서를 PDF로 바꾸고, 첨부 용량에 맞춰 파일을 줄이고,
수십 개 파일의 이름을 고칩니다. 하나하나는 어렵지 않지만 시간이 들고, 사람이 손으로 하다 보니 실수도 생깁니다.
JB업무ON은 이런 일을 **버튼 몇 번으로 끝내는 것**을 목표로 합니다.

### 흩어진 도구를 하나로

그동안 업무 도구는 필요할 때마다 하나씩 만들어 따로 배포해 왔습니다(이수증 PDF 도우미, PDF·한글 문서정리 도우미,
업무자동화 파일정리 도우미, 홈페이지 게시글 취합기 등). 쓰는 사람은 도구마다 찾아서 내려받고, 설치하고,
새 버전을 챙겨야 했습니다. JB업무ON은 도구를 한 프로그램에 모으고, 새 도구와 고친 내용을 자동 업데이트로
전달합니다. 도구 이름이 기억나지 않아도 **하려는 업무로 검색**해 찾을 수 있게 했습니다.

### 문서는 내 PC 밖으로 내보내지 않는다

교육청 업무 문서에는 성명·주민등록번호·연락처 같은 개인정보가 자주 들어 있습니다. 외부 변환 사이트에
문서를 올리지 않아도 되도록, 모든 처리를 **내 PC 안에서** 합니다. 문서 검색 색인도 PC 안에만 저장합니다.

### 교육청 업무 환경에서 그대로 동작하게

- **본청 망에서도 업데이트** — 본청에서는 GitHub 접속이 막혀 있어, 앱 업데이트를 데이터 도구실 게시글에서
  받도록 만들었습니다(자세한 배경: [docs/board-update.md](docs/board-update.md)).
- **인터넷 없이 동작** — HTML 도구가 인터넷에서 받아 오던 부품과 글꼴을 프로그램에 넣었습니다. 인터넷이 필요한
  곳은 새 버전 확인과 수집·추출 도구(게시글·학사일정 추출)뿐입니다.
- **설치 부담 없이** — 관리자 권한이 필요 없고, Python 같은 실행 환경을 따로 설치하지 않아도 됩니다.

### 처음 쓰는 사람도 바로

처음 실행하면 화면을 차례로 짚어 주는 안내가 나오고, 모든 도구 오른쪽 위의 **[사용가이드]**가
그 도구의 화면 영역을 하나씩 설명합니다. 원본을 바꾸는 작업(파일명 변경, 빈 폴더 정리 등)은 확인 칸에 표시해야
실행되게 해 실수를 막았습니다.

## 주요 기능

| 기능 | 설명 |
|---|---|
| **도구 검색** | 도구 이름이 기억나지 않아도 하려는 업무로 찾기. **Ctrl+K**로 어디서든 검색창 |
| **문서 검색** | 내 PC의 한글·PDF·엑셀·워드·PPT를 파일 이름과 본문 내용으로 찾기. 찾은 낱말이 든 문장도 함께 |
| **빠른 실행·즐겨찾기** | 자주 여는 사이트·폴더·파일·프로그램을 홈 화면 단추로 만들어 한 번에 실행. 즐겨찾기와 최근 사용 목록 |
| **단축키와 트레이 상주** | 어느 화면에서든 단축키 하나로 창을 꺼내고 숨김. 닫아도 트레이에 남아 다시 켜는 시간 없음 |
| **끌어다 놓기** | 파일·폴더를 창에 끌어다 놓으면 바로 목록에 담김. 합치는 도구는 순서 변경·이름순 정렬 |
| **사용가이드** | 모든 도구 오른쪽 위 버튼. 화면 영역을 하나씩 짚어 가며 사용법 안내 |
| **작업 완료 알림** | 창이 숨겨져 있거나 다른 창 뒤에 있으면 작업이 끝났을 때 윈도우 알림 |
| **자동 업데이트** | 새 도구·개선 기능을 알아서 받아 둠. 작업 중 갑자기 바뀌지 않게 적용 시점은 직접 선택 |

## 보안

- **문서는 PC 밖으로 나가지 않음** — 처리 대상 파일은 모두 내 PC 안에서 열리고 저장됩니다. 개인정보 마스킹·번호 검증도 마찬가지이고, 문서 검색 색인도 PC 안에만 저장합니다.
- **인터넷은 정해진 곳에서만** — 새 버전 확인과 수집·추출 도구(게시글·학사일정 추출)에서만 씁니다. 그 외 도구는 인터넷 없이 동작합니다.
- **위변조된 파일은 설치 안 됨** — 업데이트 파일은 전자서명(minisign)을 확인한 뒤에만 적용합니다. 내용이 바뀐 파일은 설치를 멈춥니다.
- **관리자 권한 없이 설치** — 사용자 계정 폴더에 설치되어 별도 권한 요청이나 시스템 변경이 없습니다.

## 설치·사용 전 확인

- 한글·워드·PPT 파일을 다루는 변환 기능은 해당 프로그램이 PC에 설치돼 있어야 동작합니다.
- 파일명 변경, 파일 꺼내기, 빈 폴더 정리처럼 원본을 바꾸는 작업은 되돌리기 어렵습니다. 중요한 자료는 미리 백업해 두세요.

## 개발자용

### 기술 구조

- **Tauri 2 + React 19 + TypeScript** — 화면과 앱 셸
- **Rust** — 도구 레지스트리, HTML 도구 로더, 문서 검색 색인, 서명 검증, 게시판 업데이트, 트레이·단축키
- **Python sidecar** — PDF·한글·엑셀 처리 로직. PyInstaller로 실행 파일 하나로 묶어 넣으므로 사용자 PC에 Python 설치 불필요
- **NSIS** — 단일 설치 파일 배포(사용자 계정 설치)

### 폴더 구조

| 경로 | 역할 |
|---|---|
| `src/` | React 화면 — 사이드바, 도구 그리드, 도구 검색, 빠른 실행, 문서 검색, 설정, 사용가이드 |
| `src-tauri/` | Rust 백엔드 — 도구 등록, HTML 로더, 문서 검색, 게시판 업데이트, 트레이 |
| `tools/<도구ID>/` | 도구 한 개당 폴더 하나. `manifest.json`으로 등록 |
| `bridge/` | 공용 Python sidecar (`runner.py`, `extra_tools.py`) |
| `scripts/` | 설치본 빌드, 버전 바꾸기, 도구 패키징, 카탈로그 서명, HTML 도구 사용가이드 넣기 |
| `tests/regression/` | 회귀 점검 |
| `docs/` | 설계 문서와 소개 영상 |

기본 도구와 `%LOCALAPPDATA%\kr.go.jbe.automation-suite\tools`의 사용자 도구를 함께 읽습니다.
같은 ID가 있으면 더 높은 버전을 사용하므로 앱 전체를 다시 설치하지 않아도 도구만 교체할 수 있습니다.

### 개발 실행

```powershell
pnpm.cmd install
pnpm.cmd tauri dev
```

### 점검

```powershell
npx tsc --noEmit -p tsconfig.json
node tests/regression/frontend_helpers.test.ts
python tests/regression/test_pdf_tools.py
python tests/regression/test_file_tools.py
python tests/regression/test_hwp_tools.py
python tests/regression/test_hwp_compress.py
```

### 설치 파일 빌드

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build_release.ps1
```

빌드할 때마다 sidecar를 PyInstaller로 새로 만들고(`-SkipSidecar`로 건너뛸 수 있음) `--selftest`로 확인한 뒤 설치본을 만들어 서명합니다.
결과물은 `src-tauri\target\release\bundle\nsis`에 생성됩니다. 버전은 `package.json`, `src-tauri/tauri.conf.json`,
`src-tauri/Cargo.toml`, `src-tauri/Cargo.lock` 네 곳을 함께 바꿉니다(`scripts/set_version.ps1`).

### 도구 추가

1. `tools\<도구ID>\manifest.json` 작성 (`id`, `name`, `top_tab`, `type`, `entry`, `description`, `order`, `enabled`, `version`, `keywords`). **BOM 없이** 저장합니다 — BOM이 있으면 도구를 건너뜁니다.
2. HTML 도구는 `web\index.html` 한 파일에 HTML·CSS·JS를 넣습니다. 사용가이드는 `scripts/html_guide/steps/<도구ID>.json`을 쓰고 `python scripts/html_guide/inject.py <도구ID>`로 넣습니다.
3. Python 도구는 `bridge/extra_tools.py`(또는 `runner.py`)의 핸들러 표에 등록하고, `src/lib/toolSchemasExtras.ts`에 입력 화면 스키마를, `src/lib/toolGuides.ts`에 사용가이드 문구를 넣습니다.
4. 앱 실행 후 설정 → 도구 레지스트리 새로고침

#### 새 Python 라이브러리가 필요할 때

1. `bridge/requirements.txt`에 라이브러리 추가
2. **`bridge/runner.spec`의 `hiddenimports`에도 추가** — 이걸 빠뜨리면 빌드는 성공하는데 실행할 때
   `ModuleNotFoundError`가 납니다. PyInstaller가 동적 import를 못 찾기 때문입니다.
3. 설치본을 다시 빌드하면 sidecar가 새로 만들어져 들어갑니다.

라이브러리가 아주 무거워서(수십 MB 이상) 모든 사용자가 받는 설치본에 넣기 부담스러우면, 그 도구만 별도 EXE로
빌드해 `manifest.json`의 `type`을 `exe`로 등록하는 방법도 있습니다.
